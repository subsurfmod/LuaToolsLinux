## 1. Executive Summary

LuaTools Linux `v4.1.2` represents a major architectural evolution, shifting from external Chromium DevTools Protocol (CDP) polling over TCP `:8080` to a **first-class, native Millennium v3.6+ plugin (`LuaToolsLinux`)** authored by **`subsurfmod`**, coupled with **multi-arch `$LIB` library routing**, **multi-user isolation**, and **kernel-level symbol interpositions** that eliminate every known crash in Valve's 64-bit Steam runtime.

## 2. Root Cause Diagnoses & Resolutions

### 2.1 Millennium v3.6+ CDP Port Deprecation
* **Root Cause**: Live inspection via `strace` and `/proc` revealed that Millennium `v3.6+` launches `steamwebhelper` with `--remote-debugging-pipe --millennium-loopback-ipc-fds=5,6`. Chromium completely disables TCP port listening (`127.0.0.1:8080`) when `--remote-debugging-pipe` is active, causing legacy CEF bridges to stall indefinitely.
* **Resolution**: Rebuilt the frontend as a native Millennium plugin (`assets/millennium_plugin/`) loaded by Millennium's internal runtime, bypassing the need for TCP `:8080`.

### 2.2 Millennium v3.6+ Lua Backend Engine Transition
* **Root Cause**: Binary disassembly of `/usr/lib/millennium/libmillennium_x64.so` revealed:
  `"skipping backend for '{}': backendType is not 'lua' (got '{}'). Python backends are no longer supported."`
* **Resolution**: Wrote the plugin backend entirely in native Lua (`backend/main.lua`) using Millennium's embedded C modules (`millennium`, `http`, `cjson.safe`, `logger`).

### 2.3 `steamwebhelper` SIGSEGV Crash (`V_strncpy`)
* **Root Cause**: Dissected coredump `core.steamwebhelper.1001....227879.zst` (`CGamepadAPITask` thread). A NULL-pointer was dereferenced at `steamclient.so + 0x2e23625` inside Valve's `V_strncpy` implementation.
* **Resolution**: Exported an inline null-safe `V_strncpy` symbol in [`bridge_lib/src/lib.rs`](file:///home/slave/Documents/LuaToolsLinux/bridge_lib/src/lib.rs), guarding against NULL source or destination pointers before delegating to `libc::strncpy`.

### 2.4 Millennium Multi-User Collision (`/tmp/millennium-mep.sock`)
* **Root Cause**: Millennium hardcodes `/tmp/millennium-mep.sock` for IPC. When multiple users run on the same system (e.g. UID 1000 and UID 1001), `bind()` threw `std::system_error` (`EADDRINUSE`) and crashed Steam immediately.
* **Resolution**: Intercepted `bind()`, `connect()`, and `unlink()` in `bridge_lib/src/lib.rs`, redirecting `/tmp/millennium-mep.sock` dynamically to `/tmp/millennium-mep-{uid}.sock`.

### 2.5 Multi-Arch `ELFCLASS32: ignored` Warnings
* **Root Cause**: Preloading a single 32-bit `libsteam_integration.so` caused `ld.so` warnings on 64-bit processes (`steamrt64/steam` and `steamwebhelper`).
* **Resolution**: Adopted glibc's dynamic multilib token `LD_PRELOAD="~/.local/lib/luatools/$LIB/libsteam_integration.so"`. Populated `~/.local/lib/luatools/lib/` (32-bit `i686`) and `~/.local/lib/luatools/lib64/` (64-bit `x86_64`).

### 2.6 Debugger/Strace Traps (`Assert(pUser)` SIGTRAP)
* **Root Cause**: Under `strace` or GDB, `steamclient.so + 0x105c78d` hit an `int3` breakpoint because `Plat_IsInDebugSession()` returned true.
* **Resolution**: Exported `Plat_IsInDebugSession()` in `bridge_lib/src/lib.rs` returning `0`, allowing full trace analysis without breakpoint halts.

## 4. Rust Companion Backend & Plugin Hardening Updates

### 4.1 [`src/services/http_server.rs`](file:///home/slave/Documents/LuaToolsLinux/src/services/http_server.rs)
* **Cryptographic Session Token & File Permissions (0600)**:
  * Generates a 32-character hex session token via `/dev/urandom` on startup.
  * Writes `$XDG_RUNTIME_DIR/luatools_rpc.json` (or `/run/user/<uid>/luatools_rpc.json`) with mode `0600` containing `{ port, url, pid, version, token }`.
  * Verifies incoming `X-LuaTools-Token` headers against `ACTIVE_SESSION_TOKEN`, rejecting unauthorized calls.
* **Deterministic Linux UID Discovery**:
  * Replaced unexported `UID` shell variable reads with `unsafe { libc::getuid() }`.
* **Ephemeral Port Fallback**:
  * If default port `6767` is occupied or restricted, `HttpServerService::start()` automatically falls back to an OS-allocated ephemeral port (`127.0.0.1:0`), records `actual_port`, and advertises it in `luatools_rpc.json`.
* **Real RPC Handler Implementations**:
  1. `SyncDlcForApp`: Reads `stplug-in/<appid>.lua` and `.lua.disabled`, parses entries via `LuaFileParser::parse_text`, extracts DLC AppIDs (`entry.id != appid`), synchronizes them into `SlssteamService` `AdditionalApps`, and persists to `config.yaml`.
  2. `SyncSlsSteamConfig`: Iterates all `.lua` manifests in `stplug-in/`, parses every script, and bulk-syncs `additional_apps`, `depot_keys`, `manifest_overrides`, `tokens`, `process_mapping`, `force_denuvo`, and `pinned_apps` to `SLSsteam` `config.yaml`.
  3. `UpdateSettingValue`: Directly mutates settings in `SettingsService` for supported keys (`fast_fetch`, `auto_update_apps`, `donate_keys`, `check_updates_on_startup`, `cef_bridge_enabled`, `http_server_enabled`, `close_to_tray`, `minimize_to_tray`, `doh_enabled`, `autostart`, `language`, `steam_path_override`, `steam_username`, `doh_endpoint`, `hubcap_api_key`) and persists via `svc.save()` / `svc.set_autostart()`.
  4. `CheckForFixes`: Separated from `OpenFix`; returns `{ "success": true, "appid": appid, "appliedFixes": [...], "availableFixes": [...], "hasFixes": bool }`.
  5. `GetBridgeDiagnostics` & `GetCompanionStatus`: Returns complete diagnostics including `preloadLib64`, `preloadLib32`, `multilibDst`, `slssteamActive`, `bridgePreloaded`, `hookCount`, `mepSocketActive`, and `ipcSocketActive`.
  6. `ToggleAppEnabled`: Atomically renames `<appid>.lua` <-> `<appid>.lua.disabled` and updates `SLSsteam` `AdditionalApps`.
  7. `ApplyRecommendedFixes`: Dispatches `RpcUiEvent::OpenFix(appid)` to the workbench.
  8. `RemoveAppliedFixes`: Invokes `AppliedFixIndexService::remove_app(appid)` and cleans applied fix records.
