## 📋 Executive Summary

**LuaToolsLinux v2.6.0 crashes the Steam main process (`steam`) with `SIGABRT` when the user clicks "Restart Steam" from the application UI.** The crash originates in our `libsteam_integration.so` (bridge_lib cdylib) during background initialization spawned by the `#[ctor]` constructor. 

Additionally, **14 steamwebhelper crashes** are captured but appear to be a separate CEF/Chromium issue in `libcef.so`.

## 🔬 Root Cause Analysis

### Crash Trigger
**User clicked "Restart Steam" from the LuaToolsLinux UI** → triggers `trigger_restart_steam()` → Millennium RPC `restart_steam` → Steam restarts → **on restart, `libsteam_integration.so` loads via `LD_PRELOAD` → `#[ctor]` runs → background thread crashes during initialization**.

### Background Thread Flow (Crash Path)
```
libsteam_integration_init() [CTOR]
  └─ thread::spawn(run_integration)
       └─ find_steam_root()
       └─ scan_steam_binaries() → finds steamclient.so, steamui.so
       └─ pattern_db.lookup_by_binary() → HTTP to GitHub/jsDelivr for steam-monitor patterns
       └─ pattern_db.lookup_by_binary() → TOML parse
       └─ client.resolve_pattern_address() for each pattern:
            - "bis_subscribed_app"
            - "get_app_id"
            - "get_app_ownership_ticket"
            - "request_encrypted_app_ticket"
            - "get_encrypted_app_ticket"
            - "get_steam_id"
            - "depot_decrypt"
       └─ patch_by_offset() → MemoryPatch::install()
            └─ mprotect() / mmap() / write_abs_jmp64()
       └─ IpcServer::start() → UnixListener::bind() → Unix domain socket
       └─ loop { thread::park_timeout() }
```

## 🔬 Root Cause Hypotheses (Ranked by Probability)

| Rank | Location | Failure Mode | Probability | Evidence |
|------|----------|--------------|-------------|----------|
| **1** | `memory_patch::install()` → `mprotect`/`mmap` | **Memory protection/trampoline allocation failure** on target address; `mprotect`/`mmap` fails due to invalid address, page permissions, ASLR layout | **HIGH** | Only syscalls in deep call chain; 12 frames in our lib |
| **2** | `resolve_pattern_address()` → returns `None` → `.unwrap()` somewhere | Pattern not found in current Steam build → `.unwrap()` on `Option` → panic → `panic = "abort"` | **HIGH** | All pattern lookups use `if let Some` but one missed `.unwrap()` possible |
| **3** | `pattern_db.lookup_by_binary()` → HTTP/TOML failure | GitHub/jsDelivr unavailable, TOML parse error, pattern file missing for current Steam build SHA-256 | **MEDIUM** | HTTP/TOML errors handled with `?` but edge cases exist |
| **4** | IPC server `UnixListener::bind()` | Socket path permission / path length / `EADDRINUSE` | **LOW** | IPC errors handled with `?` but could panic on invalid path |
| **5** | `libc::mmap`/`mprotect` in `allocate_trampoline`/`install` | Trampoline allocation failure, `mprotect` on invalid page | **MEDIUM** | `allocate_trampoline` checks `MAP_FAILED` but `mprotect` page range calc could be wrong |

### Critical Code Paths to Audit
```rust
// bridge_lib/src/lib.rs:run_integration()
1. pattern_db.lookup_by_binary() -> Result (handled)
2. pf.patterns.get("bis_subscribed_app") -> Option (if let Some)
2. entry.pattern.as_deref() -> Option (if let Some)
3. client.resolve_pattern_address() -> Option (if let Some)
4. patch_by_offset() -> Result (patch.install() -> Result)
5. IpcServer::start() -> Result (handled with ?)
```

**The `.unwrap()` / `?` usage appears correct throughout** — but **one missed `.unwrap()` or `.expect()` on a `None`/`Err` would trigger `panic = "abort"` → `SIGABRT`**.
